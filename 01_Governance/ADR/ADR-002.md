# ADR-002 — Repository Authority Placement of the Project Charter

**Document ID:** ADR-002
**Version:** 1.0.0
**Status:** Approved
**Owner:** Chief Architect / Product Owner
**Depends On:** CONST-001
**Related Artifacts:** GOV-001, Project Charter, PRD
**Date:** 2026-08-07

## 1. Status

Approved.

## 2. Context

The Authority Model required the explicit placement of the Project Charter. CONST-001 owns Purpose, Vision, Mission, Core Values, and Long-Term Philosophy; GOV-001 owns governance concepts. The Project Charter required a defined normative position without deciding the authority relationship between Architecture, Product Requirements, and Specifications.

## 3. Decision

The Project Charter is a Normative repository artifact at Authority Level 2. It is subordinate to the Constitution and Governance artifacts and authoritative only within its defined scope.

The Project Charter owns:

- Project Objectives
- Project Scope
- Project Success Criteria

It does not define constitutional concepts, governance concepts, product requirements, or architecture. Project Stakeholders and Project Business Context are deferred candidates only; they are not canonical concepts or Charter-owned cross-cutting concepts.

## 4. Rationale

This placement preserves the separation of responsibility: the Constitution defines why Aegis IOS exists, Governance defines how it is governed, and the Project Charter defines project-level objectives, boundaries, and success. Deferring the Architecture-to-Requirements relationship prevents this ADR from deciding beyond its approved scope.

## 5. Consequences

- GOV-001 can apply an explicit authority placement for the Project Charter.
- Project Objectives, Project Scope, and Project Success Criteria have a clear canonical owner.
- The Charter shall not redefine concepts owned by CONST-001 or GOV-001, architecture, or product requirements.
- A change to this authority placement requires a new ADR.

## 6. Alternatives Considered

### Alternative A — Treat the Project Charter as Informational

Rejected. The Charter owns normative project concepts.

### Alternative B — Decide the complete authority hierarchy here

Rejected. The Architecture, Product Requirements, and Specifications relationship was reserved for ADR-003.
